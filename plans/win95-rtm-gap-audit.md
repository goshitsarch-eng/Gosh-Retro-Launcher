# Plan: Windows 95 RTM fidelity gap audit

## Context

Compare the app’s current Windows 95 mode with a clean US-English Windows 95 RTM retail desktop (default 640×480, 96 DPI, standard color scheme; no Plus!, OSR2, Internet Explorer shell update, or Windows 98 additions), then define the concrete work needed to close the remaining visual and interaction gaps.

Initial findings:
- The current worktree already contains a substantial, uncommitted Win95 rebuild: dedicated Win95 shell components, RTM tokens, integer scaling, generated clean-room bitmap assets, Win95-owned dialogs/folder views/menu state, and expanded visual baselines.
- Current captures reproduce the broad RTM composition well: `#008080` desktop, canonical shell objects, 28px taskbar, gray beveled surfaces, solid navy captions, the standard Start hierarchy, and Explorer-like group windows.
- Confirmed scope is both **visual and behavioral fidelity**: icons, fonts, colors, metrics, spacing, states, menus, keyboard navigation, desktop/folder selection, taskbar behavior, window management, and Win95-style dialogs.
- The most authoritative behavioral/design source found is Microsoft’s 1995 *Windows Interface Guidelines for Software Design*. It confirms the taskbar/window model, title/system-menu behavior, menu press-drag-release and keyboard semantics, delayed cascading menus, selection rules, dialog focus/default/cancel behavior, exact four-color bevel construction, MS Sans Serif 8pt usage, and separate 16×16/32×32/48×48 icon designs.
- GUIdebook explicitly separates Windows 95 (24 Aug 1995) from Windows 95B/OSR2 and provides lossless 640×480 RTM screenshots/crops. ToastyTech explicitly labels its source as the original retail “gold” release. PCjs identifies its emulated media as the first retail 4.00.950 release. These will be the screenshot/release cross-checks; extracted icon archives are measurement-only because their Microsoft resources cannot be redistributed.
- Existing `RTM_AUDIT.md` describes the pre-rebuild state and is not yet a source-cited post-implementation comparison. Several encoded metrics are estimates contradicted by direct screenshot measurement, especially the Start menu.

### Confirmed post-rebuild gaps

| Priority | Surface | Reference finding | Current app gap |
|---|---|---|---|
| P0 | Icons | RTM icons are dense, perspective-aware, independently designed 16/32px images using deliberate masks/dither; Microsoft guidance says small icons should preserve their large counterpart rather than be mechanically reduced. | The generator scales one simple coordinate drawing into both sizes. Measured against RTM-reference extractions, current 32px My Computer occupies only 25×19/391 opaque pixels versus a full 32×32/877-pixel reference; Recycle Bin is 17×24 versus 29×32; Folder is 24×18 versus 32×27. Desktop, Start, folder, dialog, and task icons therefore read as generic placeholders rather than Win95. |
| P0 | Bitmap text | RTM screenshots use palette-clean MS Sans Serif 8pt bitmap output; guidelines specify normal weight for UI text and bold for captions/default emphasis. | The licensed recreation has useful metrics, but Chromium subpixel rasterization introduces colored fringe pixels throughout captures. Rotated Start-strip text also smooths. A deterministic monochrome bitmap-text path is needed for shell chrome/static text. |
| P0 | Frame/bevel primitives | Lossless RTM crops begin with highlight/white/face edges; guidance defines raised outer+inner and sunken outer+inner one-pixel borders. | Window/dialog CSS adds a black outer top/left edge and reverses some taskbar bevel rows. Every window and dialog is shifted by one visual edge; control border recipes are duplicated and inconsistent. |
| P0 | Dialog captions/focus | RTM Run is 347×163 with 16px `?` and Close buttons; Shut Down is 347×222 with a single Close button. Initial focus belongs in the body/default workflow. | Generic `.win95-dialog button { min-width:75px }` expands the title Close control to roughly 75px. All dialogs focus that caption control first, omit context-help variants, and do not consistently route Enter to the current default button. |
| P0 | Run/Shut Down/Find | The RTM Run crop has three 75px buttons in `OK / Cancel / Browse...` order. Shut Down has RTM radio-list spacing and `Yes / No / Help`. Find is a modeless folder-like window with Name & Location, Date Modified, and Advanced pages plus Find Now/Stop/New Search and a results view. | Run is 395×147 and orders `Browse / OK / Cancel`; Shut Down is 391×142 with two invented choices and two buttons; Find is a simplified modal `Named` list with `Open / Cancel`, no tabs/location/search controls, and no taskbar/window-manager behavior. Launcher-specific wording/actions are valid, but the RTM compositions and interaction models are not matched. |
| P1 | Start menu | Direct 640×480 gold-release measurement places the main menu around 164×236, with ~32px top rows, 32px icon slots, compact separators, and a menu top near y=217. | Current menu is about 185×273, starts near y=180, uses 36px rows and excessive content width. The second submenu uses brittle `calc(200% - 25px)` placement. Mnemonics only move selection instead of opening/activating; disabled/empty entries and submenu geometry are not part of a unified menu model. |
| P1 | Menu/input model | Guidelines require press-drag-release selection, click-to-latch, delayed cascades, Alt menu mode, wrapping arrows, per-level Escape, access-key activation, Shift+F10/Application menus, and window shortcuts including Ctrl+Esc, Windows, Windows+R/F/E/Tab, Alt+Space, and Alt+F4. | Start, popup, window, and shell keyboard listeners are independent. A single Escape can close both a submenu level and the whole Start menu; popup keyboard focus is not painted as selection; access keys do not activate popup commands; nested popup children are not implemented; bare Alt/arrow menu-bar navigation and most Windows-key shortcuts are missing. |
| P1 | Taskbar | Lossless RTM capture confirms y=452..479, `#dfdfdf` then white top bevel, a 54px Start button, no Quick Launch-style divider after Start, and a 63px tray. Task buttons resize to fit, remain when minimized, and can act as drag targets. | The top bevel order is reversed, a non-RTM divider appears after Start, the tray starts one pixel late, and active task fill uses non-palette `#b8b8b8` plus a radial gradient rather than the face/highlight checker pattern. Task buttons/background lack RTM context menus and drag-hover activation. |
| P1 | Desktop/folder selection | Guidelines specify click/right-click selection, Shift/Ctrl range/disjoint selection, white-space marquee selection, double-click/Enter default action, Shift+F10/Application context menu, inactive-selection treatment, and transfer feedback. | Desktop and folder views are single-selection only; desktop keyboard navigation is vertical only; no marquee, Ctrl/Shift selection, Ctrl+A, type-to-select, or proper translucent/dithered drag image exists. Selected icons use a solid blue rectangle plus opacity instead of `ILD_SELECTED`/50%-highlight dither semantics. Icon positions are session-only. |
| P1 | Folder views/scrollbars | RTM list views distinguish Icon, Small Icon, List, and Report modes; Report uses a real header; scroll bars have arrow buttons, proportional thumbs, disabled end states, shaft paging, auto-repeat, and keyboard scrolling. | Small and List are the same layout, Details fakes its header with CSS text, Select All is disabled, and browser pseudo-scrollbars cannot guarantee RTM arrows/thumb behavior across hosts. |
| P1 | Window behavior | Guidelines require active-only selection, single-instance reactivation, outline move/size by default, title right-click/Alt+Space menus, title-icon default Close, maximize excluding taskbar, and state restoration. | Most basic commands exist, but movement/resizing redraw live rather than with an RTM outline; the system menu has incomplete keyboard/menu semantics; minimizing/closing can select a minimized window as active; inactive folder selection remains painted; CSS title/size-grip glyphs use transforms/gradients instead of deterministic pixels. |
| P1 | Remaining launcher dialogs | RTM property sheets are tabbed with OK/Cancel/Apply semantics; Create Shortcut is a wizard; radio/check/select/text controls have standard focus, access-key, and disabled states; message boxes choose information/warning/critical symbols and the least destructive default. | Group/item properties are plain forms, Create Shortcut is a single dense form, radio/check/select rendering is browser-dependent, title controls enter the Tab order, close can silently discard transactions, and launcher Help/About/message compositions are only rough Win95 approximations. |
| P2 | Scaling/capture | Integer shell scaling is appropriate for modern displays, while original 1× logical metrics remain canonical. | Floor-sized logical roots can leave an uncovered right/bottom strip when viewport dimensions are not divisible by scale; the icon variant cap does not account cleanly for fractional devicePixelRatio above the 4× source; existing captures omit menu-bar popups, system/context menus, inactive/maximized/minimized windows, property dialogs, extended selection, drag outlines, and resize remainder cases. |

Deliberate launcher mappings are not treated as gaps: My Computer lists launcher groups; unsupported networking/recycling/system settings show an honest Win95-style notice; user groups/items live under Programs; extracted host-application icons remain user content; Shut Down affects the launcher rather than emulating the OS. Optional Inbox/MSN desktop objects varied with installed components and remain outside launcher scope.

## Approach

- Treat Microsoft’s 1995 interface guidelines as the behavioral/design authority, GUIdebook’s version-separated lossless RTM captures as the primary pixel reference, and ToastyTech/PCjs as release and screenshot cross-checks. Record URL, release confidence, capture palette/scaling caveats, and measured values in `RTM_AUDIT.md`.
- Fix global primitives before individual screens: deterministic bitmap text, border/bevel recipes, pixel glyphs, menu state/placement, selection rendering, and clean-room icon families. This prevents repeated one-off CSS corrections.
- Preserve the current clean-room policy: use original Microsoft icon extractions only to measure bounding box, palette density, metaphor, perspective, and small/large differentiation; do not copy, trace, ship, or generate from Microsoft resources. Redraw original project-owned icons as independent 16px and 32px designs and continue generating only nearest-neighbor scale variants from those sources.
- Retain the existing Win95-only shell/state/scale boundaries. Refactor components to consume shared Win95 primitives and reducers rather than replacing the architecture or touching the Win31 shell.
- Match RTM interaction semantics where they apply to launcher objects. Keep the explicitly launcher-scoped mappings honest instead of adding fake filesystem, network, Recycle Bin, Control Panel, date metadata, or OS shutdown behavior.
- Turn each confirmed mismatch into a deterministic scenario or pure reducer/geometry test before accepting a new baseline.

### Reference set

- Microsoft, *The Windows Interface Guidelines for Software Design* (1995 scan): https://www.ics.uci.edu/~kobsa/courses/ICS104/course-notes/Microsoft_WindowsGuidelines.pdf — shell/taskbar pp. 15–21; windows pp. 75–96; menus pp. 97–120; secondary windows pp. 143–175; visual design pp. 317–337; mouse/keyboard summaries pp. 357–361 in the scan’s printed pagination.
- GUIdebook Windows 95 release page and version-separated screenshot set: https://guidebookgallery.org/guis/windows/win95 and https://guidebookgallery.org/screenshots/win95
- Lossless GUIdebook references used for direct measurement: [empty 640×480 desktop](https://guidebookgallery.org/pics/gui/desktop/empty/win95.png), [file-manager window](https://guidebookgallery.org/pics/gui/system/managers/filemanager/win95.png), [Run](https://guidebookgallery.org/pics/gui/system/features/run/win95.png), [Find](https://guidebookgallery.org/pics/gui/system/features/search/win95-1-1.png), and [Shut Down](https://guidebookgallery.org/pics/gui/startupshutdown/shutdownwindow/win95.png).
- ToastyTech’s explicitly identified original retail “gold” desktop/Start/Explorer/Find captures: https://toastytech.com/guis/win95.html and https://toastytech.com/guis/win952.html (geometry evidence only where its capture palette is shifted).
- PCjs first retail 4.00.950 media/build identification: https://pcjs.jdmulloy.com/software/pcx86/sys/windows/win95/4.00.950/
- Microsoft shell-version documentation, used to exclude IE-integrated shell/Win98 features: https://learn.microsoft.com/en-us/windows/win32/shell/versions (`shell32.dll` 4.0 for original Windows 95; 4.71/4.72 for later IE-integrated shells/Windows 98).
- Microsoft common-controls documentation for selection drawing: https://learn.microsoft.com/en-us/windows/win32/controls/imagelistdrawflags and https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-imagelist_draw (`ILD_SELECTED == ILD_BLEND50`; 50% system-highlight blend), plus https://learn.microsoft.com/en-us/windows/win32/controls/list-view-item-states for focused/selected state semantics.
- Windows Icon Archive/React95 extractions may be used only as a non-redistributed cross-check for native icon dimensions, palettes, and resource identity; they are not implementation assets: https://limehawk.github.io/windows-icon-archive/ and https://github.com/React95/React95/tree/master/packages/icons

## Reuse

- Keep the verified values and correct the measured estimates in `src/renderer/src/shells/win95/tokens.ts`; retain `Win95ScaleContext.tsx` and the logical point/delta/geometry conversion model.
- Retain the generated-asset pipeline and lookup API in `iconCatalog.ts` / `scripts/generate-win95-assets.cjs`, but replace the drawings with independently authored 16px/32px sources and generate only higher integer variants.
- Reuse the shell/component boundaries already established by `Win95Shell`, `Win95Desktop`, `Win95Taskbar`, `Win95StartMenu`, `Win95Window`, `Win95FolderView`, `Win95Dialogs`, and `Win95Menu`; consolidate their duplicated visuals/input logic into Win95-owned primitives.
- Extend the pure reducers/stores already present in `menuState.ts`, `taskbarState.ts`, `geometry.ts`, and `windowStore.ts` instead of moving Win95 back into shared Win31 MDI/UI state.
- Reuse `settings.autoArrange`, shell-specific `ProgramGroup.shellWindowState.win95`, `programStore` CRUD, `window.electronAPI.program.launch`, extracted host icons, and `programSearch.ts`; add only Win95-specific position fields if manual layout persistence is implemented.
- Reuse the current `quickSearchOpen` request channel as the trigger for Win95 Find, but present it through the Win95 window manager; leave `QuickSearchOverlay` unchanged for Win31.
- Extend the deterministic Win95 fixture/scenarios in `scripts/capture-wfw.cjs` and the existing pure Win95 tests rather than adding another harness.
- Preserve the existing font recreation and attribution as the glyph source; generate deterministic monochrome normal/bold bitmap atlases from it rather than relying on Chromium to rasterize shell chrome text.

## Verification

- At 640×480/1×, compare each deterministic state against its cited RTM reference. Require exact canonical palette values and primitive edge order; verify measured taskbar y=452–479, Start/tray geometry, menu bounds/rows, 18px captions, 20px menu bars, 16/32px icon canvases, and exact 347×163 Run / 347×222 Shut Down outer dimensions. Use overlays/pixel sampling only on lossless, unscaled references; use geometry and visual review rather than raw pixel thresholds for palette-shifted/compressed sources and clean-room icons.

Confirm static shell text contains no colored subpixel fringe in captures.
- Exercise mouse semantics end to end: select/Ctrl/Shift/marquee/type-to-select; desktop and folder context menus; double-click default action; icon drag/snap/Auto Arrange; Start press-drag-release and delayed submenu corridors; menu-bar and nested popup tracking; task switching/minimize/restore/context menus; outline move/eight-edge resize; caption/system controls; scrollbar arrows/shaft/thumb/auto-repeat; drag-hover task activation; and modal backdrop behavior.
