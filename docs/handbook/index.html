Overview

What Program Manager is, what this handbook covers, and how much of it was verified.

What the application does

Verified at runtimeConfirmed in source

Program Manager is a launcher that looks like four classic desktops. You organize programs, web links, scripts and folders into groups, then open them from the desktop that matches your taste:

  • Windows for Workgroups 3.11: a Program Manager window with group windows inside it.
  • Windows 95: a desktop with a taskbar, Start menu, folder windows, Find and Run.
  • Classic Mac OS: a menu bar, a Launcher HD disk window, folder windows and Get Info.
  • BeOS: a Deskbar, tabbed windows and a Find window.

All four shells read and write the same data file, so switching desktops does not change your groups. The shell is chosen in Launcher Tools and can also be changed from the Windows 95 Shut Down dialog.

Getting started

Run the program from source, make your first group, and find the data file. Steps marked with a status tag say how each one was verified.

Requirements

Verified at runtimeConfirmed in source
  • To run from source: Godot 4.7 standard build. Version 4.7.2 is the latest stable release and the one used for every run in this audit. The .NET build is not needed.
  • Operating systems: Windows, macOS and Linux have export presets. Only macOS was run during the audit. Windows and Linux builds were exported but not run.
  • Network: none. The program makes no internet requests. Its only socket is a loopback lock that stops a second copy from starting (see Architecture).
  • Display: the main window opens at 640 by 480 and can be resized. Small window sizes were not tested, so their layout is unverified. Each desktop keeps its own scale (Auto, 1×, 2×, 3× or 4×). Launcher Tools shows one scale box, for the scale of the selected desktop.

Verified at runtimeConfirmed in source

Clone the repository, then start the project from its folder:

First launch

Confirmed in source
  • The program starts in the Windows for Workgroups 3.11 desktop, because the default shell is win31 (src/core/types.gd).
  • If no data file exists, the program starts with an empty workspace. No groups are created for you.
  • Options > Settings… opens the settings dialog (finding W31-001, fixed). Its Add Starter Groups button adds the reference groups. The button was checked in code and not clicked during the audit.
  • The data file is written when something changes. Nothing is written just by starting the program.

Quick start: your first group and program

Confirmed in sourceWindows for Workgroups 3.11 shell
  1. In the Program Manager window, choose File > New…. The New Program Object dialog opens.
  2. Select Program Group and choose OK. The New Program Group dialog opens with an empty Description field.
  3. Type a name such as Utilities and choose OK. A group window with that name opens inside Program Manager.
  4. Make sure the new group is selected (click its window). Choose File > New… again, select Program Item and choose OK. The Program Item radio is disabled while no group exists.
  5. Fill in Description (the name shown under the icon) and Command Line (the program to start, for example a full path to an executable). Leave Launch Group as None unless you want the item in a batch. Choose OK.
  6. Double-click the new icon, or select it and press Enter. The program starts.

Expected result: the item appears in the group window with the icon you chose, and launching it starts the command. Launch behaviour for each kind of file is listed under Launching programs in the user manual.

Where your data is stored

Confirmed in sourceUnit tests: round trip and restart

Everything is kept in one JSON file named program-manager-data.json. The folder depends on your system:

SystemData folder
Windows%APPDATA%\program-manager
macOS~/Library/Application Support/program-manager
Linux$XDG_CONFIG_HOME/program-manager, or ~/.config/program-manager when XDG_CONFIG_HOME is not set
Any systemThe folder named by the environment variable PM_USER_DATA, when it is set. The capture harness and the test suite use this.

Automatic backups are kept in a backups folder inside the same data folder. See Backups and recovery in the user manual.

The unit tests include a store round trip: the data is saved, the store is reopened, and the groups are read back. They also test export and import. That covers the file format, not the interface.

Choose a different desktop

Confirmed in source

Open Launcher Tools and choose the desktop under Shell and appearance. The four choices are Windows for Workgroups 3.11, Windows 95, Classic Mac OS and BeOS. Choose Apply. The window switches to the new desktop and keeps the same groups.

Launcher Tools is reached from the Windows for Workgroups Launcher menu, from Windows 95 Start > Settings > Launcher Tools, from the Mac logo menu, from the BeOS Deskbar, from the tray menu, or with Ctrl+Alt+T in every desktop.

Adding, editing and deleting in Program Manager

Confirmed in sourceDialogs captured
  1. New group: File > New…, choose Program Group, OK, type a Description, OK.
  2. New item: select a group, File > New…, choose Program Item, OK. Fill in the fields below, then OK.
  3. Edit: select an item or group and choose File > Properties… or press Alt+Enter.
  4. Move or copy: File > Move… or File > Copy… asks for the target group.
  5. Delete: select the item or group, then press Delete or choose File > Delete. You are asked to confirm. Deleting a group also removes every item in it. Only the launcher's entry is removed. No file on disk is touched.

Program Item fields: Description, Command Line, Working Directory, Arguments, Environment (one KEY=VALUE per line), Shortcut Key, Run (Normal Window, Minimized or Maximized), Launch Group (None or Group 1 to 8) and Icon. Use Browse… to pick a file and Change Icon… to pick an icon. The Windows for Workgroups picker offers 23 icons.

Launch group numbers above 8: the data file and an import can hold any whole number of 0 or more, and such a number is kept and run. The item editors offer only None and 1 to 8. Known gap: for a stored 9, the Windows for Workgroups Properties dialog shows None and saves 8 on OK, the BeOS Get Info window shows an empty Batch group and saves 8, the Launcher Tools Batch group box shows 8 and saves 8, and the Mac Get Info dialog shows None and saves 0 (None).

Program Group fields: Description, Group File (read-only), Icon and Change Icon…. The dialog has a Delete button.

Known gaps: Shortcut Key works only in the Windows for Workgroups shell, and the navigation keys never start an item (see Launching programs). Rename is done through the group's Description field, because Program Manager has no separate Rename command.

Windows 95 desktop

Captured at runtimeConfirmed in sourceWindows 95 shell

The desktop has three icons: My Computer (opens a window listing your groups as folders), Network Neighborhood and Recycle Bin. Network Neighborhood only shows a message that network browsing is not available. Recycle Bin shows a message that the launcher does not keep deleted files there. The taskbar holds the Start button, one button per open window, and a clock.

Start menu: Programs (your groups, then their items), Documents (always empty), Settings (Launcher Tools… works; Control Panel, Printers and Taskbar… show a message), Find (Files or Folders… works; Computer and On the Internet… show a message), Help (the two-pane help window; only its first topic can be read), Run… and Shut Down….

Shut Down… offers Shut down the launcher, Restart the launcher and Restart in Windows for Workgroups 3.11. The MS-DOS mode option is disabled. Restart the launcher only closes the open windows; it does not reload your data. Only Shut down quits the program.

Folder windows open from My Computer or from a group. They have Large Icons, Small Icons, List and Details views, Ctrl and Shift selection, a marquee drag, type-to-select, and Ctrl+A. Right-click menus open when the button is pressed.

Classic Mac OS desktop

Captured at runtimeConfirmed in sourceClassic Mac OS shell

  • Logo menu: Launcher Tools…, Desktop Pictures…, Find… (Cmd+F), then one entry per group.
  • File: New Folder, Open, Close Window, Get Info, Duplicate, Move To Trash. In a folder window, New Program and New Website are also offered.

Finding programs

Captured at runtimeConfirmed in source
  • Windows for Workgroups 3.11 Quick Search: type part of a name, path or group name. Use Up and Down to move through up to 10 results, Enter to start one, Escape to close.
  • Windows 95 Find: Start > Find > Files or Folders…. Named accepts * and ? wildcards. Look in chooses all groups or one group. Run a command

Captured at runtimeConfirmed in source

Run… starts whatever you type, using the same launching rules as a program item. It is in the Windows for Workgroups File menu, the Windows 95 Start menu (Win+R or Cmd+R on macOS), the Mac Special menu (Cmd+R), and the BeOS Deskbar menu. The Windows 95 Run history lasts only as long as the program is open.

Running text you type can start any program on your computer. Only type commands you trust.

What happens when you launch an item

Confirmed in sourceWindows not run

The launcher chooses a method from the file type and the operating system (src/core/launcher.gd):

TargetMethod
Windows .exe or .comWith no arguments, working folder, environment variables or run mode, it is handed straight to the system's shell open. With arguments only, it is started directly. With a working folder, environment variables, or Run set to Minimized or Maximized, it is started through a PowerShell wrapper so these apply. If the item has no arguments and its working folder is missing or PowerShell is blocked or missing, it still starts through the shell open, but without its working folder, environment variables or run mode.
Windows .bat or .cmdRun by cmd /d /s /c through the ComSpec variable.
Windows .lnkThe shortcut is read and its target is launched.
macOS .appOpened with open -a.
macOS and Linux executablesStarted directly, with their working folder.
Linux .desktopThe Exec= line is read, its field codes such as %f are removed, and the command is started.
Other filesOpened with the operating system's default handler.
http:// or https:// addressesOpened in the default browser. On Windows, other address schemes are refused.

A program that cannot be found is reported before anything starts: Program not found: …. A working folder that cannot be found is reported as Working directory not found: …. Two Windows exceptions: (a) a .exe or .com with no arguments, working folder, environment variables or run mode is started directly by the system, so a missing file gives the system's own error message, not Program not found; (b) a .exe or .com with no arguments still starts when its working folder is missing or PowerShell is blocked, but without its working folder, environment variables or run mode.

Known gaps in launching:

  • The PowerShell wrapper reports through its exit code: 0 means started, 2 means Windows refused to start the program (its message is shown, and there is no fallback), and 3 means the wrapper was blocked before it could try. Exit 3, or a PowerShell that cannot run, uses the shell-open fallback described above when the item has no arguments, and is reported as a failure otherwise (CORE-11). None of this was run on Windows.
  • Run modes other than Normal work only for Windows .exe and .com files (CORE-09).
  • Arguments given to .bat and .cmd files are parsed by cmd.exe, so characters such as & keep their shell meaning (CORE-06).
  • An item's Shortcut Key works only in the Windows for Workgroups shell. Enter, Escape, Tab, Space, Backspace, Delete, the arrow keys, Home, End, Page Up and Page Down never start an item. Imported shortcut keys without Ctrl, Alt, Shift or Meta are cleared on import. The item editor does not require a modifier, so a bare key you type yourself, such as F5, starts the item whenever it is pressed on the Windows for Workgroups desktop.

Batch launch: Launch All and launch groups

Confirmed in sourceLaunch Group menu captured
  1. Give an item a Launch Group number from 1 to 8 in its properties. Items with the same number form one batch. The stored value is a whole number of 0 or more, where 0 means None; a number above 8 from an older file or an import is kept.
  2. Choose Launch All (Windows for Workgroups Launcher menu, Mac Special menu, or BeOS Deskbar menu) to run every batch in ascending order, including numbers above 8. To run one batch, choose its Launch Group n entry instead. Each entry shows how many items it will start.
  3. Items inside a batch start one after another. The pause between items is the Delay between items setting in Launcher Tools. It defaults to 500 ms, and the control accepts 100 to 5000 ms in steps of 100. There is no pause between one batch and the next.
  4. A batch can hold at most 200 items.

Limits: nothing cancels a batch once it has started. A failed item does not stop the rest of the batch. Two defects affect what you see: the BeOS Launch All message can show the wrong group numbers (BE-01), and the item editors cannot show a group number above 8. Opening such an item and choosing OK changes it: Windows for Workgroups Properties, BeOS Get Info and the Launcher Tools Batch group box save 8, and Mac Get Info saves None. See the audit findings for details.

Confirmed in sourceGlobal hotkey not tested
  • Shortcut: Ctrl+Shift+Space, or Cmd+Shift+Space on macOS, opens Quick Search while the program has focus.

Backups, restore points and recovery

Confirmed in sourceRestore not exercised in the UI
  • Automatic backups: the program keeps copies of the data file in the backups folder inside the data folder. A backup is made when groups, settings or profiles change, when the store is replaced or cleared, and as a manual restore point. Automatic backups are made at most once every 30 seconds.
  • Retention: the 12 newest backups are kept. Older ones are deleted when the limit is reached. Manual restore points are kept under the same limit, so a long run of automatic backups can push them out (CORE-05, still open).
  • Restore points and restore: Launcher Tools > Backup and recovery lists the backups. Restore asks first: Restore the backup from …? Your current data is backed up first. One safety backup of the current data is written before anything is replaced. If that backup cannot be written, the restore is refused and nothing changes.
  • When a save fails: if your groups, settings or workspace profiles cannot be written to the data file (for example, the disk is full or the file is read-only), a message box tells you. The change is kept in memory and stays pending. Groups and settings are tried again at the next save of the same kind, profiles at the next save of any kind, and everything when you quit. The same message is shown once, not on every retry. A failure with a different message is shown when it happens, and the same message is shown again if a save of that kind has worked in between.
  • Damaged data file: if the data file cannot be read, the damaged file is copied beside the original with a .corrupt- name, and the newest backup is restored. The source reads this path, but it was not run in this audit.
  • Reset: deleting the data file gives you an empty workspace the next time you start. The backups folder is not removed, so delete it too for a clean start.

Back up before you experiment: quit the program, then copy the whole data folder. Restoring means putting the copy back while the program is closed.

Import and export

Confirmed in sourceNative file dialogs not exercised
  • Where: Launcher Tools, section Windows 3.x groups. The buttons are Export JSON…, Import JSON…, Export .GRP… and Import .GRP….
  • JSON export writes the whole configuration (groups, items, settings and workspace profiles) to a file you choose. The suggested name is program-manager-backup.json.
  • JSON import replaces the current groups, settings and workspace profiles. Before replacing them, the program writes a backup of the current data. If that backup cannot be written, or the imported data cannot be saved, the import is refused and nothing changes. If the file is malformed, you see Invalid file format, Invalid group or item data in file or Failed to read file, and nothing changes. Files over 10 MB are refused.
  • Repairs: imported values are checked. A launch group that is not a whole number of 0 or more becomes 0 (numbers above 8 are kept), a setting with the wrong type or range takes its default, and a shortcut key without Ctrl, Alt, Shift or Meta is cleared. The Launcher Tools status line says how many values were repaired and how many shortcut keys were cleared, and a notice in the main window repeats it.
  • .GRP files are the Windows 3.x group format. Export names the file after the group. Import adds the group to your workspace, under a new id if its id is already in use.
  • Import never starts a program by itself.

Startup, shell switching and the single instance

Confirmed in sourceCaptured with each shell
  1. Startup (src/app/main.gd, _ready): unless the run is a capture or the single-instance check is disabled, the program asks the running copy to show itself and quits if one answers. Then ProgramStore.init_store() loads the data file.
  2. Shell creation: the chosen shell is created (Win31Shell.new(), Win95Shell.new(), MacShell.new() or BeShell.new()), its request signals are connected to Platform and to main, and it is added to the window.
  3. Switching: the old shell is removed and freed, and the new one is created. Window positions for the Windows for Workgroups and Windows 95 shells are kept in the data file. Classic Mac OS and BeOS window positions are kept for the session only.
  4. Single instance: the first copy listens on a loopback TCP port (127.0.0.1) derived from the data folder. A second copy connects, sends SHOW (or QUICKSEARCH), and quits when the first copy answers. There is no lock file, so a crash never leaves a stale lock.

Data flow of a launch

Confirmed in sourceLaunch scenarios ran

A single launch from a shell goes through Platform.launch. A batch calls Launcher.launch_program for each item in turn, with the delay between items. Find results go back to the shell's launch_item.

On Windows, a .exe that needs a working folder, environment or a window style (Launcher.plan_spawn) is started by a PowerShell ProcessStartInfo wrapper run synchronously. Launcher.powershell_route checks the program and folder first; interpret_powershell_result reads the wrapper's exit code (0 started, 2 Process.Start threw, 3 blocked before Process.Start). When the wrapper is unavailable or blocked, can_fall_back_to_shell_open allows the system's shell open for a .exe or .com with no arguments; exit 2 is reported as an error without a fallback. This path was not run on Windows.

Data flow of saving, backing up and starting

Confirmed in sourceUnit tests: round trip and restart

Saves are made under a temporary name first, so an interrupted save leaves the previous file in place. The backup lane only runs when a change happens.

The settings change path persists first and then applies the change. Each backup's file name records the reason for it, for example groups changed or settings changed.

Concurrency, timers and external communication

Confirmed in source
  • Program code runs on the main thread and uses signals, timers and await. The test scenarios use the same mechanisms.
  • There is one background thread, in src/platform/desktop_bridge.gd. It reads the output of the Windows helper process that registers the global shortcut.
  • The program makes no network requests. The only socket is the loopback listener of the single-instance check (see Startup above). Nothing is sent to a remote server.
  • Changes to groups and settings are saved 300 ms after the last change, by a debounce timer in ProgramStore (SAVE_DEBOUNCE). Pending changes are written when the program exits. Window-position changes are saved the same way when Save Settings on Exit is on.
  • Automatic backups are checked on each change and made at most every 30 seconds. An idle program does not write files.

The data model

Confirmed in source
  • The data file is JSON. Its current schemaVersion is 5 (src/core/types.gd, CURRENT_SCHEMA_VERSION).
  • Top-level keys: schemaVersion, groups, settings and workspaceProfiles.
  • A group holds an id, a name, an icon, its items and window state for each desktop. An item holds its name, path (the command), arguments, working directory, environment, run mode, launch group, shortcut key and icon, plus its position on each desktop.
  • Migration (migration.gd) turns older data into the current schema and normalises it. A launch group must be a whole number of 0 or more (0 means None; numbers above 8 are kept, and Launch All runs every positive number in ascending order); any other value becomes 0 (validators.gd, launch_groups.gd); a known setting with the wrong type or range takes its default; unknown keys are kept. Profiles are normalised like groups. Imports are normalised the same way, and shortcut keys without a modifier are cleared on import only (CORE-01 and CORE-02 are fixed).
  • A save repairs invalid data before it writes and reports the repair. Every repaired value is counted, including a missing or wrong-type list or settings container. If a groups, settings or workspace profile save fails (invalid data or a write error), ProgramStore emits save_failed, the host shows a notice, and the change stays pending. Groups and settings are retried by the next flush of their own kind, profiles by the next flush of any kind, and all of them by the flush on exit. The first success after a failure emits save_recovered (program_store.gd, main.gd).
  • Restore (ProgramStore.restore_backup) and JSON import (ProgramStore.import_from) each write one forced safety backup of the current data first. If that backup cannot be written, save_failed("backup") is emitted and nothing is replaced; if the new data cannot be written to the store file, the operation is refused and the data stays as it was (Persistence.set_all_data also refuses when its own backup fails).
  • The Windows 3.x .GRP format is converted to and from the same group structure by grp.gd. Windows shortcut files are read by lnk_file.gd.

Troubleshooting

Each entry starts from what you see: an exact message, or a behaviour. The cause and fix come from the code or from a run during this audit. Entries say which of the two they are.

The macOS export stops with “Cannot export for universal or arm64”

ReproducedFixed in commit 65aca64
Message
Cannot export for universal or arm64 if ETC2 ASTC texture format is disabled. Enable it in the Project Settings (Rendering > Textures > VRAM Compression > Import ETC2 ASTC).
Cause
The macOS preset builds a universal binary, but the project does not enable ETC2 ASTC import, which is off by default.
Fix
Fixed in commit 65aca64. project.godot now sets textures/vram_compression/import_etc2_astc=true under [rendering]. With that setting, all five export presets exit with status 0. If you copy the project into a new project file, keep the setting.

The Windows export prints “Icon size … is missing”

Reproduced
Message
WARNING: Resources Modification: Icon size "16" is missing. The same warning appears for 32, 48, 64 and 128. The export still succeeds.
Cause
resources/icon.ico holds one 256 by 256 image. Windows scales it for small sizes, which looks poor in small views.
Fix
Regenerate resources/icon.ico with the 16, 32, 48, 64, 128 and 256 pixel frames. Not done in this audit.

The unit test run ends with leak warnings

Reproduced
Message
WARNING: 1 RID of type "CanvasItem" was leaked. WARNING: 5 ObjectDB instances were leaked at exit. ERROR: 2 resources still in use at exit.
Cause
Objects still alive when the test process exits. The engine reports them at shutdown.
What it means
The summary line still reads 541 tests, 0 failed, and the run exits with status 0. CI does not check for these lines. The cause was not traced to a test.

“Only http and https URLs are allowed”

Confirmed in source
Cause
A web item or a URL in Launcher Tools uses another scheme, such as file: or a custom protocol. The check is in src/app/platform.gd (open_external).
Fix
Use an address that starts with http:// or https://. Local files should be added as program items instead.

“Program not found” when launching an item

Confirmed in source
Cause
The file named in the item's Command Line does not exist at that path, or it is not an executable the launcher can start. The message comes from src/core/launcher.gd. On Windows, a .exe or .com with no arguments, working folder, environment variables or run mode is started directly by the system, so a missing file shows the system's own error message instead.
Fix
Open the item's properties, choose Browse… and pick the file again. On Linux, a .desktop file needs a valid Exec= line.

Import fails with “Invalid file format”, “Invalid group or item data” or “Failed to read file”

Confirmed in source
Cause
The file is not a Program Manager export, it is damaged, it has a group or item that does not match the format, or it is larger than 10 MB. Nothing is changed when an import fails. The import is also refused, with nothing changed, when the backup of your current data cannot be written (Could not back up your current data before importing, so the file was not imported.) or when the imported data cannot be saved (Failed to save the imported data).
Fix
Export again from the source computer and check that the file opens as JSON. For older Windows 3.x files, use the .GRP import instead of JSON import.

Starting the program brings up the window that is already open

Confirmed in source
Cause
This is the single-instance check. The second copy asks the first to show itself and then quits.
Fix
To run a second copy on purpose (for example in a test), set PM_NO_SINGLE_INSTANCE=1 or pass --no-single-instance. Each data folder has its own port, so two data folders can run side by side.

“Restart the launcher” did not reload my data

Confirmed in source
Cause
On the Windows 95 desktop this command closes the open windows and redraws the frame. It does not reload the data file or create a new shell (finding W95-003).
Fix
Quit the program and start it again to reload everything. Use Restart in Windows for Workgroups 3.11 to switch desktops.

A batch launch starts programs more slowly than I expected

Confirmed in source
Cause
Each item in a batch waits for the Delay between items setting, which defaults to 500 ms. There is no pause between batches, and nothing can cancel a batch once it has started.
Fix
Lower the delay in Launcher Tools (100 ms is the minimum), or move items into smaller batches.

My real data changed after I ran a capture or a script

Fixed in this revisionChecked with HOME set to a temporary folder
Cause
Before the fix, the capture harness ran the normal startup code, which loaded and could rewrite the data file, before it switched to its fixture folder. If PM_USER_DATA was not set, that file was your real one (CORE-14).
Now
A capture run selects its temporary profile before the store opens, so it does not read the real data file. The fix was checked by running a capture with HOME set to a temporary folder and PM_USER_DATA unset: the data file was written only inside the capture's own folder.
What to do
Set PM_USER_DATA in your own scripts anyway. If an earlier run changed your data, restore the copy from the backups folder in the data folder, or from your own copy.

Confirmed in sourceNot seen on a real desktop
Cause
The tray uses the status-indicator feature of the desktop. If the desktop does not provide it, no icon is shown (src/platform/tray_controller.gd).

Install or enable your desktop's status-indicator support. Closing the window still keeps the program running, because the window is minimized rather than hidden.

Pressing Enter starts a program I did not choose

Fixed in this revision
Cause
Before the fix, an item whose Shortcut Key was a bare key such as enter could start when that key was pressed in the Program Manager window, with no dialog or text box focused (CORE-02). Such a value could come from an imported file.

If you set a Shortcut Key yourself, use one with Ctrl, Alt, Shift or Meta: the item editor accepts a bare key such as F5, and only import clears bare keys. Check imported items before you use them.

CORE-02 · Imported shortcut keys can start an item on an ordinary key press

MediumFixed in this revisionCore, app, platform and toolkit

Status. Navigation keys never act as item shortcuts (test_win31_nav_shortcuts). Imported shortcut keys without a modifier are cleared on import (test_import_normalization). The item editor still accepts a bare key such as F5, which then starts the item on the WfW desktop.

• Evidence:
