# Desktop audit, 19 November 2026

**The recorded functional walkthrough and final release smoke tests passed on Windows, macOS and Linux.** This audit fixed 27 application, packaging, documentation and test defects against Program Manager 2.0.0 at `5f8c918`. Full visual and platform sign-off remains open. The historical reference renders differ, the debug driver retains script resources at shutdown, and some OS-owned interactions have limited coverage.

## Builds and environment

The source version is **2.0.0**. The baseline was commit **5f8c91891050047fb6e4239dad95d64799db14c2**. The corrections in this report are working-tree changes. Godot **4.7.2.stable.official.ed1daf0bf** ran the project and produced the release exports. The launcher is a GDScript desktop application using Godot's Compatibility renderer. `project.godot` starts `src/app/main.tscn`. The main scene mounts one of four desktop shells. ProgramStore, UIState, MdiState, Platform and Sounds are autoloads. Data, settings, saved workspaces and backups live outside the application. Every destructive scenario in this audit used a disposable profile. The on-screen WfW and child-window layouts are distinct from the native host rectangle. The host starts at its shell-specific initial size and centers on launch. The maximize regression checks restoration within the running session.

|---|---|
| macOS 27.0.1, build 26A434 | Apple M2 Max, Retina, native ARM64 editor and universal app. Also launched the x86-64 slice under Rosetta. OpenGL compatibility on Metal. |

From a clean checkout, install Godot and its matching export templates, run `godot --headless --path . --import`, then `godot --path .`. Run the suite with `godot --headless --path . --script tests/run_tests.gd`. For the interactive WfW flow use `godot --path . tests/visual/dialogs_driver.tscn -- --flow` on a display. The five export presets, NSIS recipe, Debian packaging script and macOS packaging workflow are the shipping entry points. The README now includes the clean import and output-directory steps. ## Interactive walkthrough and regression evidence

The initial sweep and the regression sweep operated rendered application windows. The menu driver restored its fixture before each leaf, opened the menu, hovered through cascading menus, clicked the final row, and recorded the resulting modal and group/item counts. The form driver reopened forms between cases, interacted with actual widgets and recorded the new dialog or edited field. These are observations of activation and state. Where correctness depended on disk output, the selected group, a child process or UI geometry, there were separate checks.

## Automated coverage

Three new unit methods cover the displayed URL destination and saved program metadata, Mac note-dialog focus and cancellation, and viewport-limited zoom. Existing cases gained assertions for stale destination groups, malformed imports and valid/unsupported icon data. Platform fixture changes use Windows file URIs and native editing modifiers, and avoid Unix permission cleanup on Windows. The visual and unit runners now expose failures through their process exit status. The macOS CI workflow opens a fresh ZIP and runs the signed executable before packaging. The new desktop window regression operates the actual WfW system menu and compares the restored rectangle with its starting size and position.

## Verification and limits

- **Automated suite.** The runner enumerated 779 tests on each OS. Windows printed seven skips for POSIX read-only-directory cases because its fixture remained writable. The Debian run used an unprivileged account and exercised the permission failures. Expected error-path output includes refused writes, malformed imports and backup failures. The negative control for a script exception was run separately.
- **Rendering.** The macOS run met the repository's 0.5% pixel threshold on one of 43 legacy reference frames. Forty exceeded it. Two odd-sized references rounded down on Retina. Repeating those two on 1× Linux produced the exact reference dimensions, with 7.315% and 0.702% differing pixels. The older assets and additional menu entries explain visible differences. The complete set has no pixel-parity sign-off.
- **Teardown diagnostics.** The standalone debug WfW dialog driver passed all 22 interactions and then reported three GL textures, two font RIDs and outstanding script resources at engine shutdown. The long all-shell instrumented scene also reported outstanding resources on exit. Removing its UI and waiting eight frames did not clear the script references. Clearing font and texture caches in a diagnostic copy removed the GL allocations from that diagnostic, while script references remained. Each ordinary macOS shell was also run in a separate release process and its exit logs inspected. A minimal headless process reproduced 19 retained resources by loading the WfW dialog-layer script without instantiating any UI. Loading the dialog driver alone retained 29. Loading the ordinary main script alone and running the standard editor entry point produced no such diagnostics. The debug-script reference retention remains unresolved. A forced early quit during the startup chime also produced an audio-resource warning. Normal-duration packaged runs exited cleanly.
- **Desktop integration.** macOS status-menu Show, Launcher Tools, Quick Search, a group item, the disabled empty group and Exit were exercised. The application menu's Settings command and both application-defined Dock commands were activated. Windows and Linux second-instance handoff and reopening the persisted workspace were exercised in separate processes. On Windows, closing the window after its PowerShell helper registered hid the HWND, and the global Ctrl+Shift+Space shortcut restored it. The Windows 11 notification-area UI did not expose the launcher icon by name to UI Automation, so the individual Windows tray menu entries have no click result. Closing during helper startup fell back to minimizing. On Linux, a second run with an XFCE notification area confirmed the StatusNotifier host was registered. Godot 4.7.2’s X11 display server still returned false for FEATURE_STATUS_INDICATOR, and the app had no tray menu there. Linux audio used a dummy device. The Intel macOS and x86-64 Windows runs used the ARM hosts' translation layers. Wayland, physical multi-monitor DPI transitions, hardware audio fidelity, accessibility with a human screen reader and signed/notarized distribution through OS reputation services have no result here.
- **Meaning of the checklist.** The menus, forms and Tools lists enumerate the tested fixture states. A click with no modal or count change is recorded as an activation. Individual external programs, every possible imported workspace, every permutation of permissions, IMEs and OS-owned file picker controls do not have independent end-to-end assertions. No claim of exhaustive coverage of those combinations is made.
